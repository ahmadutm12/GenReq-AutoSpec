# GenReq-AutoSpec — Replication Package

Replication package for the paper:

> **GenReq-AutoSpec: Human-in-the-Loop LLM Classification and Grounded Refinement of Software Requirements — An Empirical Evaluation on PROMISE NFR**
> [Authors — to be added] · Submitted to *e-Informatica Software Engineering Journal* · DOI: [Zenodo DOI — to be added]

The package contains everything needed to recompute every number, table and figure in the paper:
the benchmark data, the exact prompts, the label-free inputs sent to the LLMs, all recorded LLM outputs,
the manual audit, and the analysis scripts.

## What the study does

| Experiment | Research question | Data |
|---|---|---|
| Zero-shot FR/NFR classification (Module 3) vs. keyword and TF-IDF baselines (10-fold and leave-one-project-out) | RQ1, RQ2 | All 625 PROMISE NFR statements |
| Uncertainty flag as a trigger for human review | RQ2 | All 625 statements |
| Controlled (grounded) vs. unconstrained LLM refinement (Modules 4–5) | RQ3 | 80 statements, stratified sample |
| Memorisation probe | Threats to validity | 60 statements |

## Repository layout

```
.
├── data/              PROMISE NFR source files and derived study files (see data/README.md)
├── prompts/           The three prompts exactly as used (classification, controlled, unconstrained)
├── llm_inputs/        Label-free inputs sent to the LLMs (classification batches, probe prefixes)
├── ref_inputs/        Label-free inputs for the refinement experiment (80 statements)
├── llm_outputs/       Recorded LLM outputs (JSON Lines), one record per statement
│   ├── A_batch*.jsonl, B_batch*.jsonl     classification by LLM-A and LLM-B
│   ├── REF_controlled_*.jsonl             controlled refinement (LLM-A)
│   ├── REF_unconstrained_*.jsonl          unconstrained refinement (LLM-A)
│   └── probe_completions.jsonl            memorisation probe (LLM-A)
├── annotations/       Manual audit of flagged unsupported numbers
├── scripts/           Analysis scripts, run in numeric order
├── results/           Generated result tables (CSV/JSON)
├── figures/           Generated figures
└── run_all.sh         Runs the whole analysis
```

## Reproducing the results

Requires Python ≥ 3.10.

```bash
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
bash run_all.sh                                          # Windows: run the scripts in scripts/ in numeric order
```

`run_all.sh` regenerates all files in `results/` and `figures/` from `data/`, `llm_outputs/` and `annotations/`.
A clean run reproduces the released result files byte-for-byte (tested with Python 3.13, scikit-learn 1.9.1).

| Script | Produces | Paper |
|---|---|---|
| `00_prepare_data.py` | derived data files, LLM input batches, refinement sample, probe inputs | §4.1, §4.5, §4.6 |
| `01_baselines.py` | majority, keyword and TF-IDF (SVM, LR) predictions; 10-fold and LOPO | §4.3 |
| `02_evaluate_classification.py` | binary metrics, CIs, McNemar/Holm, κ, four-class results, uncertainty routing | Tables 3–6 |
| `03_eval_relabel_subset.py` | results on the 532 unambiguous statements | §5.2 |
| `04_evaluate_refinement.py` | grounding and quality indicators, Wilcoxon tests | Table 7 |
| `05_audited_mcnemar.py` | McNemar test on audited unsupported numbers | §5.3 |
| `06_probe_eval.py` | memorisation probe | §5.4 |
| `07_figures.py` | `figures/fig2_macroF1.png`, `figures/fig3_refinement.png` | Figures 2–3 |

## LLM configuration

| Label | Model | Used for |
|---|---|---|
| LLM-A | Claude Opus 5.5 (`claude-opus-5-5`), Anthropic | classification, refinement, probe |
| LLM-B | Claude Haiku 5.5 (`claude-haiku-5-5`), Anthropic | classification |

Models were accessed in November 2026 with the provider's default decoding settings; each condition was run once.
The models received only the prompt and the statements (ids and text) — no labels, project ids or other files.
The prompts in `prompts/` were fixed before any output was inspected and were not tuned on PROMISE.

**The LLM outputs are not regenerated by `run_all.sh`.** Model versions change and sampling is stochastic, so a new
run will not reproduce the outputs exactly; the recorded outputs in `llm_outputs/` are the data analysed in the paper.
To run your own model, send each line of `llm_inputs/*.jsonl` or `ref_inputs/*.jsonl` with the matching prompt and
save the responses in the same JSON Lines format.

## Output formats

Classification (`A_*.jsonl`, `B_*.jsonl`):
```json
{"id": "R001", "label4": "NFR", "binary": "NFR", "confidence": "high", "rationale": "..."}
```
Refinement (`REF_*.jsonl`):
```json
{"id": "R402", "candidates": ["The website shall ..."], "open_questions": ["..."]}
```

## Manual audit

`annotations/unsupported_number_audit.csv` lists every rewrite in which the automatic detector found a number absent
from the source (26 items) and the manual decision: *genuine unsupported addition* (22) or *false positive* —
an equivalent re-expression such as "1/4" → "25%" (4). The audit was performed by one analyst.
